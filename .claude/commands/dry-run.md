Прогони дневной запуск бота на копии реального состояния и разбери результат: что нашлось,
что было бы опубликовано и как это выглядит для читателя канала. Ничего не постится и ничего
не пишется в базу — публикатор в dry-run печатает в stdout, транзакция откатывается.

Аргументы: $ARGUMENTS

## Подготовка

Работай в `/tmp`, а не в репозитории: рабочая база `lexinform.db` и `LEXINFORM_DB_PATH` из
`.env` не должны быть затронуты, дампы в репозиторий не попадают.

```bash
git fetch -q origin state
git show origin/state:lexinform.sql > /tmp/lexinform-state.sql
export LEXINFORM_DB_PATH=/tmp/lexinform-dryrun.db
rm -f "$LEXINFORM_DB_PATH"
uv run lexinform db init && uv run lexinform db restore /tmp/lexinform-state.sql
uv run lexinform show 2699   # sanity check: дамп мигрировал, строки читаются
```

Если `db restore` падает — это и есть находка: дамп с прода не переживает текущие миграции,
дальше не иди, разберись с этим.

## Прогон

```bash
uv run lexinform run --dry-run --max-analyze 0 $ARGUMENTS
```

- **`--max-analyze 0` по умолчанию**: `run --dry-run` делает настоящие вызовы модели и стоит
  денег. Убирай его только если в аргументах есть `--analyze` (тогда ставь небольшой лимит,
  например `--max-analyze 2`, и скажи в отчёте, сколько потрачено по полю `llm_usage`).
- `--since` без аргумента — берётся watermark из состояния; для проверки конкретного окна
  передавай дату.
- RCL: страница проекта рендерится ~10 с, бэклог в несколько дней — это минуты. Если RCL
  недоступен (`Request Rejected`, таймаут) — это отдельная находка, а не повод чинить прогон;
  повторить можно с `--no-rcl`.
- `--full-track` заставляет проверить все отслеживаемые законопроекты, а не только изменённые:
  так видно карточки, которые дрейфуют (CardRefresher), и напоминания о сроках.

## Что показать в итоге

1. Сводка отчёта: фазы, `discovered/analyzed/published/updates`, ошибки, пропуски по причинам
   (`skipped_cost`, `skipped_closed`, `skipped_prefilter`, …), `wykaz_backlog`, стоимость.
2. **Каждое сообщение, которое ушло бы в канал — целиком, как его увидит читатель** (карточки,
   апдейты, ответы-реплаи, напоминания). Не пересказывай: приводи текст.
3. Аномалии, отсортированные по тому, насколько они мешают читателю:
   - сообщение, которое обещает действие, которого уже нет, или молчит там, где окно открыто;
   - «что дальше», не совпадающее со стадиями (см. инварианты про `End`, `closureDate`,
     `passed`, вакацио легис в CLAUDE.md);
   - недоступный источник, который уронил свою фазу;
   - законопроект, застрявший в статусе с непустым `last_error`.
4. Вывод одной фразой: прогон здоров или нет, и что чинить первым.

Код по ходу не правь — если нашёл баг, покажи находку и предложи правку отдельно.
