## Что решаем

Оценить отдельно пригодность для поиска по корпусу, подготовки проверяемых выдержек,
единственного текстового входа в анализ, отрицательного keyword-фильтра, сравнения
редакций и восстановления таблиц. Проверить цену по времени, памяти и объёму входа LLM.

Эксперимент проводится вне окружения приложения. Исходные PDF и кеши корпуса сохраняются;
production, state, публикации и платные модельные вызовы в него не входят. Независимый
holdout не используется, новые юридические метки корпуса не создаются.

## Наборы и проверки

| Набор | Что проверяем |
| --- | --- |
| Все 24 записи `print.scan` | Устойчивость на настоящих сканах, страницы и ошибки; полный прогон при допустимых ресурсах |
| Смешанные PDF и RCL | Текст рядом со сканами, письма, проекты и ответы на консультации |
| Около 12 нормативных и 6 табличных страниц | Парное сравнение native text и распознавания тех же страниц после растрирования |
| Чистые и ухудшенные изображения | 250 DPI; отдельно 150 DPI, небольшой поворот, размытие и JPEG |
| Известные контрольные ответы | Польские буквы, даты, суммы, отрицания, область действия, ссылки, сроки и таблицы |
| Слепые визуальные фрагменты | Отдельный агент выписывает критичные фрагменты до просмотра OCR |
| Операционные проверки | Повторы, пустые/повреждённые файлы, ограничения страниц, отказ отсутствующего backend |

Native extraction является приближённым эталоном. Порядок чтения, пробелы, сноски и таблицы
проверяются визуально; высокий CER на таблице нельзя автоматически называть потерей текста.
Визуальная транскрипция агента также не равна независимой человеческой разметке.

Считаются CER/WER с NFC и нормализацией пробелов, сохранение чисел и отрицаний, точных
контрольных фрагментов и изменений, связей «строка — столбец — значение». Символьное
сходство и наличие всех слов не доказывают правильность юридического смысла или таблицы.

Для Lexinform отдельно проверяются решения `KeywordPrefilter` и отпечатки `law_digest`.
Результаты на страницах не выдаются за recall целых законопроектов. Объём текста в токенах
сравнивается с проектной оценкой сканов; фактическую экономию API это не устанавливает.

## Критерии решения

Поисковый вспомогательный слой допустим при полезном восстановлении текста, сохранённой
ссылке на оригинал/страницу, явной маркировке OCR и прозрачных ошибках. Поиск не гарантирует
полноту, поэтому отсутствие совпадения не позволяет отвергнуть документ.

Единственный вход юридического анализа, автоматический отказ и вывод о тождестве редакций
требуют сохранения всех проверенных критичных фактов/изменений и отсутствия новых ложных
отказов. Найденная критичная ошибка блокирует безусловное применение. Даже ноль ошибок в
малой выборке означает основание только для ограниченного пилота.

Для таблиц проверяется принадлежность значения нужной строке и колонке, включая объединённые
заголовки и авторство высказываний. Confidence и плотность текста не заменяют эти проверки.

## Дополнения протокола

Первоначальная парная выборка содержала лишь одну страницу, положительную для keyword-фильтра.
До OCR новой ветки добавлен отдельный набор: семь страниц возле порога, три насыщенные
положительные и два отрицательных контроля, каждый в двух вариантах изображения. Это
намеренно обогащённый тест устойчивости, а не оценка частоты ошибок во всём корпусе.

Для существующего OCR-слоя добавлены первые две записи `pdf.ocr_scan`: сравнение PDF и
растрированной первой страницы. Сохранены отдельные источники и результаты этой диагностики.

Восстановление таблиц дополнительно проверено для Tesseract с тем же LayoutNet, затем
для вывода Markdown. Формат JSON сам по себе не заполняет поле `page.markdown`.

Поворот ухудшенных корпусных страниц расширяет белый холст; у синтетических контролей
холст фиксированный. Оба фактически использованных преобразования сохранены в scripts,
их результаты не объединяются в оценку одной распределённой случайной выборки.
