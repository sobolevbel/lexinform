# Проверка полезности и решение о выпуске

Статус: протокол подготовлен; human/model acceptance и production rollout не выполнены · 14 октября 2026.
Основа: [план](2026-10-13-message-usefulness.md), [журнал реализации](2026-10-13-message-usefulness-progress.md).

## Локальная проверка

Первый выпуск: P0 неизвестного решения, первый экран, физическая доставка, digest ownership,
новизна, повестка и операторские статусы. Второй: результаты консультаций. Третий:
окончательный акт и дополнительные даты. Каждый выпуск оценивается отдельно; средний
балл не компенсирует потерянное участие, неверный исход/срок или повторную доставку.

Офлайн-инструменты запускаются из repository; dump и полный корпус остаются за его пределами:

```bash
uv run python tools/message_usefulness_audit.py STATE.sql OUTPUT
uv run python tools/message_usefulness_digest_audit.py STATE.sql OUTPUT 2026-W41
uv run python tools/message_usefulness_review_audit.py CORPUS RESPONSE.txt MANIFEST.json --final-act-text ACT.txt
```

Manifest должен сохранять SHA кода и implementation hashes, SHA исходного dump/corpus,
период, число payload, локали, exclusions и основание оценки. Frozen HTML проверяется
как прежняя отправка; текущий formatter на сохранённом snapshot — отдельный candidate,
который не подменяет историю. Код audit не создаёт production pipeline, credentials или LLM calls.

Редактор проверяет пары: topic/event/action в первом блоке; круг лиц, ограничения,
суммы/даты/отрицания/ссылки; неизвестность; сроки с маршрутом и источником; parent и части.
Матрица включает исходные 12 видов, все event keys исторической рубрики и новые kinds.
Нужны обычный и крайний случай, отсутствие analysis/name/date, joint prints, veto/pilny,
перенос/снятие/отмена, split и полный restart/recovery. Нет snapshot — нет утверждения
об историческом тексте. Synthetic regressions не являются историческими payload.

Последовательности для просмотра: 2644 принятие → поздние голоса; RPW → druk 3039;
wykaz → RCL → Sejm; консультация → документы → подтверждённый результат;
подпись → Dz.U. → общая дата → поздний разбор → дополнительная дата.
В первом выпуске сохраняется прежний путь отправки для shadow; сравниваются proposed destination
и все защищённые окна. Ни один digest-only источник не теряется при отказе/unknown части.

## Отдельная source/model QA

Перед включением новых purposes требуется достаточная независимая разметка обоих источников,
а не только положительные fixtures: отказ, partial, ответ без изменения, позиции без ответа,
сканы, несколько противоречащих версий, новый текст и сохранённое сравнение. Для окончательных
актов: разные даты, переходные/retroactive нормы, разные группы, старые/новые заявления,
условный запуск и отсутствие текста. Проверяются не только цитаты, но и смысл русских выводов.

Текущая выборка RCL и окончательного акта подтверждает конкретные правила контракта;
live Sejm report был недоступен из-за WAF. Она не подтверждает общую точность новой модели
на всех practical-impact выводах. Платный A/B проводится по отдельному разрешению с заранее
оценённой стоимостью, одинаковыми документами, слепой разметкой и сохранёнными ответами.
Defaults новых purposes остаются выключенными до этого решения.

## Читательская проверка

После отдельного согласия набрать 5–8 добровольцев с разными задачами. Не отправлять
приглашения автоматически. Сбалансировать порядок старого и нового формата между людьми;
не давать одинаковое событие подряд. Каждый пример должен иметь эталон ответа,
подготовленный по источнику до исследования.

Для каждого сообщения спросить: о чём дело; что изменилось; касается ли оно человека;
какое действие доступно; до какой даты и куда подавать. Отдельно записывать необходимость
открыть давнюю карточку. Время чтения и предпочтение формата — вторичные показатели.
Ответ «действовать пока нельзя, результат неизвестен» может быть правильным.
Не выдавать preference за понимание, а скорость за правильность.

Сохранять обезличенные ответы, ошибки и рубрику 0–2 по пяти измерениям, сумму минимум 1.
Неверный опасный исход/срок ограничивает результат четырьмя. Исторические экспертные
оценки не смешиваются с новым reader measurement.

## Решение и контроль

Локальная реализация не включает production variables, push/merge, LLM experiment или sends.
Разрешение на выпуск должно назвать состав этапов и режимы reader_attention/daily/new purposes.
В журнале записать commit, schema, проверенные manifests, ограничения и ответственное решение.

После включения наблюдать первые полные циклы с одобренным дайджестом: покрытие,
потерянные действия, повторные исходы, возраст очередей, unknown части и дополнительные затраты.
При ложном исходе/сроке, двойной доставке, нарушении parent/membership или неподтверждённом
совете остановить новый выпуск, исправить и повторить затронутый replay.

Off меняет будущие и не начатые решения; frozen/unknown остаются прежними. SQL downgrade нет:
rollback требует совместимого кода либо прежнего dump и сверки событий после restore.
