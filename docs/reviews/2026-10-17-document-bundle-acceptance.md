# Проверка комплекта и решение по LLM

Статус: локальная реализация E0/E1 и завершённая экспериментальная проверка E2, 17 октября 2026.
Реализация E1 — `bc94e04`; основание — `204fea9` и [план](../plans/2026-10-17-document-selection-evidence.md).
**Модельную интеграцию останавливаем на E2:** дополнительное разрешение неоднозначностей
составило 1 из 10 (10%) у обоих профилей при требуемых 20%.
E3, дополнительный раунд E4 и эксплуатационные shadow/on из E5 не выполняются по условию плана.
Детерминированные проверки E5 включены в E1. Порты, очереди и Senate-specific `DocumentWork` сохранены.

## Что реализовано

Чистая проверка комплекта связывает основной текст, нормативные продолжения, собственные
приложения и справочные части. `DocumentLink` хранит тип связи, индексы частей, состояние
confirmed/unknown/conflicting и ссылки на типизированные факты с дословными фрагментами.
`DocumentCoverage` раздельно хранит покрытие извлечения и окончательного входа анализа.
Наблюдавшиеся части ZIP сохраняются отдельно от выбранных; перед сохранением полный текст
обоих наборов убирается, а хеши, координаты, цитаты и ограничения остаются.
Новые JSON-поля имеют совместимые значения по умолчанию; миграция SQLite не требуется.

Собственные ссылки с «do niniejszej ustawy»/«do projektu ustawy» проверяются по номеру и
заголовку приложения. Учтены приложения внутри основного файла и обязательного продолжения,
включая начало после PDF page break. Ссылка на приложение старого акта не требует его загрузки.
Неопределённая ссылка «do ustawy» внутри изменяемой статьи не доказывает отсутствие нового
приложения. Доступное приложение без установленной связи даёт unverified, доказанное
недостающее собственное приложение — waiting, известный конфликт — ambiguous.
Чужое приложение к rozporządzenie не подтверждает нормативный комплект закона.

Обоснование/OSR сопоставляются по собственной помете редакции и по узкому классу явно
сопоставимых денежных норм: тот же art./ust. проекта, одна сумма, PLN/злоты и тот же вид
величины. Минимумы, максимумы, несколько сумм, другая статья, валюта и несопоставимые
величины остаются неизвестными. Это ограниченная сверка, не универсальный анализ смысла.
Неизменённый старый OSR может иметь подтверждённое совпадение нормы; несовпадение дат само
по себе не объявляется конфликтом. Неизвестная применимость явно передаётся в prompt как
ограничение справочного материала. Смена prompt не запускает повторный анализ истории.

Байты, извлечение и нормативный комплект имеют разные хеши. Равные байты одной роли
объединяются; изменение только приложения/обязательного тома меняет нормативный хеш.
Приложения упорядочиваются по собственному номеру и содержанию, а не имени или порядку ZIP.
Окончательный вход проверяется после trimming и cost fitting: потерянная нормативная часть
снимает selected и сохраняет `normative_text_omitted`. Разные собственные даты в основном
тексте или обязательных томах дают конфликт с исходными цитатами.
Официальный RCL URL с явным чужим ID исключается источником до загрузки; остальные кандидаты
продолжают проверяться. Generic loader не ветвится по источнику.

## E0: независимая проверочная выборка

Заморожены 60 сценариев: 20 tuning и 40 holdout, связанные проекты не пересекают границу.
Tuning сохраняет прежние регрессии B97/B99/B100, cover-only, чужой проект, собственные даты,
UD409 и защитные 672258/711610/778150. Это диагностические сценарии, не 20 независимых проектов.
Holdout содержит 20 пар «закон/справочный документ», 10 писем без нормативного текста и
10 остаточных пар представлений с одинаковой распознанной датой. Подвыборка детерминированная
и стратифицированная; она не является случайной оценкой всей популяции.

Manifest содержит официальные URL/ID, byte SHA, SHA сохранённого извлечения, показанные
диапазоны и block ID, разметку ролей/дат/предпочтения и ожидаемый нормативный кандидат.
Небольшие тексты показаны полностью; большие — head 1800 + tail 600 с явным excerpts_only.
Рекомендация файла не сертифицирует полноту прочих страниц или приложений. В h08 требуемые
приложения отдельно отмечены как не подтверждённые; выбор основного файла этого не отменяет.
Исходники корпуса не изменялись. Hash `cases.json` зафиксирован в intent до token count/submit;
ожидаемые ответы не передавались модели и после результатов не менялись.

Замороженный baseline — Python-снимок поверх `204fea9` с текущей на момент submit проверкой E1,
а не чистый checkout этого коммита; его исходники и SHA сохранены. Он имел 39/40 совпадений рекомендаций. Из десяти ambiguous-пар девять
обоснованно оставались неоднозначными. В h34 (12390651, документы 705153/688101) собственная
помета aktualizacja 14.02.2025 устанавливает порядок поверх общей даты projektu 18.10.2024;
замороженное правило её не распознавало. На момент E2 этот случай сохранялся,
под ответ модели парсер не расширялся; последующее исправление описано в дополнении ниже.
Последующие исправления проверки комплекта не изменили эти показатели рекомендаций.

## E2: одинаковый настоящий batch

Один batch, 80 запросов: те же 40 вопросов, блоки и JSON-схема для Sonnet 5.5 и Haiku 5.5,
оба effort=low, max_output=1200. Все 80 завершились успешно, усечений и ошибок провайдера нет.
Время от создания до окончания batch — 8 минут 31 секунда; задержка production не измерялась.

| Показатель | Sonnet 5.5 | Haiku 5.5 |
| --- | --- | --- |
| Рекомендация совпала с разметкой | 40/40 | 40/40 |
| Все размеченные факты роли/даты правильны | 40/40 | 28/40 |
| Все цитаты дословные в исходном ответе | 34/40 | 33/40 |
| Принято строгим офлайн-проверяющим после уникального whitespace recovery | 28/40 | 26/40 |
| Неправильно предпочёл кандидата | 0 | 0 |
| Предпочтение с ошибочным/непринятым основанием | 9 | 4 |
| Добавил корректное разрешение к 10 неоднозначностям baseline | 1 (10%) | 1 (10%) |
| Фактическая стоимость | $0,240118 | $0,0155794 |

Haiku ошиблась в 18 размеченных фактах в 12 ответах, в частности принимала дату письма за дату
редакции. У Sonnet размеченные факты правильны, но не все цитаты достаточно обосновывают их.
Whitespace recovery восстановил 6 цитат Sonnet и 9 Haiku; слова/числа/пунктуация не исправлялись.
Исходные ответы сохранены отдельно от восстановленных оснований.

Строгая проверка дополнительно требует собственный USTAWA в цитате роли и дату в заголовке
до Art. 1. Она консервативна: закон может быть правильно распознан по статье, а такое основание
этот проверяющий отклонит. Поэтому 28/40 и 26/40 не являются точностью рекомендаций и могут
недооценивать пригодность цитат. Протокол смысловой проверки записан до чтения результатов;
сохранены первая оценка и итог с уточнёнными именами счётчиков. Независимо от ослабления
проверки цитат сырой дополнительный выигрыш остаётся 1/10, ниже порога продолжения.
Ноль неверных preferred ID на 40 сценариях не доказывает надёжность на всей популяции.

Стоимость новых запросов — **$0,2556974**, суммарная исследовательская — **$1,4216765**.
Зарезервированный максимум до submit — $0,4885839; соблюдены дополнительные $0,50 и общие $2.
Расчёт использует batch input/output usage и [тарифы Anthropic](https://platform.claude.com/docs/en/about-claude/pricing).
Runner теперь резервирует также прежние открытые/неопределённые intents и после collect
фиксирует actual cost и complete. Открытых intents этого эксперимента нет; повторный submit не нужен.

## Корпус и регрессии

| Проверка | Результат |
| --- | --- |
| 4 276 snapshots / 825 RCL | selected 1 832 → 2 261; unverified 1 383 → 922; waiting 53 → 85; ambiguous 132, unsupported 671, no_candidate 205 без изменений |
| Все изменения относительно `204fea9` | 438 unverified → selected; 32 unverified → waiting; 9 selected → unverified. Выбранные URL и длины текстов не изменились |
| 69 исходных ZIP, 11 786 print metadata | Выбор, тексты, digest и проверки мутаций совпали с baseline |
| Повторное чтение 19 исходников и переупаковка девяти комплектов | 18 прямых/обратных ZIP/URL контролей и 45 смысловых мутаций прошли |
| Защитный Senate replay | Те же 701 выбора и 23 PDF-кандидата, 4 903 мутации и 11 391 отрицательный контроль |

Для каждого изменившегося снимка сохранены прежнее/новое решение, типизированные факты,
связи и фрагменты упоминаний приложений. Новые подтверждения возникают при отсутствии
собственных приложений в нормативной части или при явной внешней ссылке; упоминания в
обосновании больше не подменяют требования закона. Сомнительная принадлежность приложения
не стала автоматическим подтверждением. Ссылка «do ustawy» в изменяемой статье остаётся
неизвестной, а не объявляется собственным отсутствующим приложением.
Проверка корректировалась по всем найденным переходам: учтены доступные приложения с
неполным заголовком, одинаковые номера старого и нового приложения и PDF page breaks.

32 новых waiting означают явную собственную ссылку без соответствующей доступной части
в этом cached replay; это не 32 доказанных production-инцидента. Часть тела, таблица или
заголовок могут отсутствовать в кэшированном извлечении. Девять прежних selected потеряли
доказанную полноту, сохранив выбранный текст и явное неизвестное основание.
Отдельно проверены 10 реальных денежных норм с контролируемым обоснованием и изменением
суммы: совпадение и конфликт распознаются во всех 10 парах. Пределы и несопоставимые нормы
исключены, поэтому это положительный контроль, а не оценка полноты обнаружения конфликтов.
Повторно извлечены 672258/711610/778150/785848: исходные нормативные части сохранены,
у 778150 и 785848 связь приложений остаётся unknown, а не missing.
132 ambiguous-снимка остаются конфликтами редакций; в этом снимке нет отдельного массового
класса неразрешённой роли. Результат E2 поэтому не доказывает бесполезность LLM для любого
будущего класса ошибок.

Регрессии через World покрывают workers=1/4, ограничение входа, одинаковые байты по разным URL,
чужой проект, предупреждение о справочной части и отсутствие повторного анализа.
Чистые проверки покрывают отсутствующие/неясные/чужие приложения, inline annex, обязательные
тома, сумму той же нормы, несопоставимые числа, конфликт собственных дат и text-free restore.
Метаморфные проверки ZIP/URL дополнены двумя приложениями с перестановкой и переименованием.

**2 435 passed, 32 deselected**, strict mypy — 288 файлов и отдельно два research tools;
Ruff check/format и `git diff --check` прошли. CLI/wiring не менялись, local_http не требовался.
Строгая сборка и проверка ссылок портала выполнены отдельно.

Production state, публикации и история не изменялись; pipeline/backfill не запускались.
Push, CI, deploy и фактическое поведение production не подтверждались.

## Дополнение: собственная помета aktualizacja

После завершения E2 владелец отдельно запросил исправить известный h34. Парсер теперь
учитывает явную помету `Projekt …, aktualizacja …` в собственном заголовке до USTAWA/Art. 1.
Дата обновления заменяет исходную дату, а факт сохраняет весь фрагмент с обеими датами.
Поддержаны словесная, числовая и разделённая пробелами формы. Невозможная дата, обновление
раньше исходной редакции и несколько конкурирующих помет не устанавливают порядок.
Отдельная дата OSR, письма или упоминание актуализации в статьях не заменяют дату проекта.

Для реальной пары требовалось также закончить название закона перед заголовком `Rozdział …`:
прежнее сравнение включало различающиеся «Przepis ogólny»/«Przepisy ogólne» первой главы
в предмет закона и потому блокировало выбор даже при правильно распознанной дате.
Оба ограничения исправлены общей чистой политикой; ZIP и отдельные URL используют её одинаково.

На 10 411 сохранённых текстах изменились только две даты: 705153 и 705164,
18.10.2024 → 14.02.2025. Сокращены 254 названия перед заголовком главы; ни одно не стало пустым.
Полный replay 4 276 снимков 825 RCL изменил ровно два решения: 12390651/4 — ambiguous →
selected (705153), 12390652/4 — ambiguous → unverified (705164). У второго не объявляется
подтверждённая полнота комплекта. Остальные решения без изменений; разобраны оба перехода,
официальные связи, заголовки и собственные даты обоих конкурентов.

Повторно прочитаны 22 исходника; 20 проверок прямого/обратного порядка ZIP/URL и 50 мутаций
дат, сумм, отрицаний, scope и ссылок прошли. В том числе реальная пара 705153/688101 даёт
новую редакцию одинаково в обеих упаковках. Все 69 прежних ZIP и метаданные 11 786 друков
сохранили результаты. Cached replay не подтверждает полноту отсутствующих извлечений/сканов;
защитный Senate baseline в этом дополнении отдельно не перезапускался.

Итог дополнения: **2 449 passed, 32 deselected**, strict mypy 288 файлов и отдельно corpus runner,
Ruff check/format, `git diff --check` и строгий `make docs-check`. Production не запускался.

Повторить офлайн после распаковки manifest/results:

```bash
uv run --no-sync python -m tools.evaluate_document_selection manifest.json /path/to/lexinform-corpus evaluation.json --results results.json
uv run --no-sync python tools/replay_document_candidates.py /path/to/lexinform-corpus candidates.json
uv run --no-sync python tools/replay_document_selection.py /path/to/lexinform-corpus packages.json
uv run --no-sync python tools/validate_document_policy.py /path/to/lexinform-corpus controls.json
```

Cached replay не доказывает байтовую/страничную полноту каждого исходника и не охватывает
отсутствующие извлечения, сканы и неподдерживаемые форматы. Реальная переупаковка и Senate
baseline проверены отдельно. Суммы проверяются только в ограниченном явно сопоставимом
классе; положительные мутации не измеряют полноту обнаружения всех конфликтов.
Перестановка A/B и misleading names исследовались в предыдущем диагностическом пилоте;
новый holdout не добавляет независимого модельного повтора для каждого такого изменения.
E2 не пройден и автоматический выбор по модели не включается даже для проверенного класса.
