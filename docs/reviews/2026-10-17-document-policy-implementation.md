# Общая политика редакций и проверяемые основания

Статус: локальная реализация и корпусная проверка 17 октября 2026.
Исходная версия — `3f01768`. Выполнена первая детерминированная поставка
[плана](../plans/2026-10-17-document-selection-evidence.md); условные модельные этапы не включены.

## Изменения

Сравнение нормативных редакций вынесено в `comparable_versions`. ZIP и отдельные URL теперь
используют один порядок: подтверждённая роль закона, одинаковый предмет либо общий изменяемый
акт, собственные даты всех сопоставляемых редакций, затем конфликт нормативного содержания.
Равная дата не разрешает конфликт; имя, формат, порядок и дата загрузки не устанавливают редакцию.

Первый коммит `39dd415` вынес сравнение без изменения выбранных URL, состояний и текстов.
В пяти ambiguous-снимках расширился только диагностический список конфликтующих кандидатов:
в него попали также прежние редакции. Это отдельно видно при сравнении сохранённых результатов.
Следующая поставка объединяет правила обоих путей и меняет распознавание даты.

Парсер понимает числовую и польскую словесную дату после `Projekt`, запятую, `Projekt ustawy`,
пробелы вокруг разделителей, дату отдельной строкой и пробелы между числами. Сохранены
проверенные заголовки `Etap: … (projekt …)`, `Wersja3,0 Projekt …` и ведущий символ обратной
кавычки из извлечения 484427. Поиск ограничен начальным заголовком до USTAWA/Art. 1;
конфликт собственных дат и невозможная дата не устанавливают порядок. Дата цитируемого акта
или упоминание проекта в письме не подменяют редакцию.

`DocumentFact` хранит тип и значение факта, происхождение, индекс части и ID блока, URL,
SHA извлечённого текста, точные символьные координаты и исходную цитату. Принадлежность
ссылается на официальную связь источника, а роль, дата и покрытие — на текст выбранной части.
Проверяются идентичность источника, хеш, координаты и цитата. `selected` требует четыре вида
оснований у одной основной части без известных потерь. Проверка находится в чистой функции
`bill_selection`, загрузчик отвечает за загрузку и кэш.

Строковые поля читаются для совместимости, но не подтверждают старое `selected`: без новых
фактов оно становится `unverified`. JSON совместим без новой миграции. После сохранения
полный текст частей убирается; короткие цитаты и исходные хеши сохраняются. Дата OSR не
подтверждает дату закона. Неизвестная применимость справочных частей явно отмечена
`support_applicability_unknown`; это ограничение справочного материала, а не отказ от текста закона.

Порты, batch lifecycle, pending work и очереди доставки сохранены. `DocumentWork` по-прежнему
хранит Senate-specific исторический контекст; второй потребитель и универсальный resolver не добавлены.

Рассмотрены заголовки и предметные основания всех новых выборов. Десять проектов:
12379853, 12381402, 12383805, 12384252, 12385657, 12386151, 12386961, 12388950,
12391953, 12396602. Новый порядок в последнем устанавливается собственной датой на строке
после PROJEKT. Сохранены старые рабочие заголовки с Etap/Wersja и переносами строк:
пробный более строгий вариант исключал их, но в итоговую поставку эта регрессия не вошла.

Одна из девяти переупакованных групп, 711607/701927, остаётся ambiguous в обоих путях:
сноски текущего извлечения меняют предметные признаки. У остальных восьми комплектов выбран
одинаковый текст; только два имеют все основания для selected, шесть остаются unverified.
Это подтверждает независимость от упаковки, а не полную пригодность каждого файла.

Повторить из корня репозитория без сети и моделей:

```bash
uv run --no-sync python tools/replay_document_candidates.py /path/to/lexinform-corpus /tmp/candidates.json
uv run --no-sync python tools/replay_document_selection.py /path/to/lexinform-corpus /tmp/packages.json
uv run --no-sync python tools/validate_document_policy.py /path/to/lexinform-corpus /tmp/policy.json
uv run --no-sync python tools/replay_senate_documents.py /path/to/senate-supplement /path/to/lexinform-corpus /tmp/senate.json
```

Cached replay не подтверждает исходные байты, сканы, отсутствующие извлечения и полную
структуру каждого ZIP. 19 исходников проверены отдельно; переупаковка сохраняет тексты,
а не исходные байты и вёрстку. Выборка диагностическая, не независимый holdout из 40 дел.
Совпадение дат не разрешает различия представлений и не доказывает эквивалентность норм.
Общий изменяемый акт используется только внутри официально связанного набора кандидатов.

Покрытие здесь означает известный текст до нормы о вступлении в силу с учётом заявленных
потерь и приложений; это не юридическая сертификация полного нормативного комплекта.
Проверка применимости каждого OSR, предметная сверка конкретных норм и более точное
доказательство принадлежности приложений остаются отдельной работой E1.2. Расширенная
независимая выборка E0 требуется до нового модельного эксперимента. E2–E5 не разрешают
интеграцию LLM без доказанной дополнительной пользы; новых платных вызовов не было.

## Проверки и выпуск

Регрессии проверяют собственные и посторонние даты, невозможные и конфликтующие значения,
равную дату при изменённых нормах, перестановку и упаковку, цитаты, подмену URL, неполные
основания и text-free restore. Сценарии World с workers=1/4 сохраняют факты через dump/restore
и не повторяют анализ. Итог: **2 399 passed, 32 deselected**; strict mypy проверил
284 файла и отдельно новый corpus runner. Ruff/format, `git diff --check`
и строгий `make docs-check` прошли. Локальный HTTP CLI gate не требовался:
порты, wiring и CLI не менялись.

Ни production state, ни публикации не изменялись; pipeline и backfill не запускались.
Push, CI, deploy и живое поведение production этой локальной приёмкой не подтверждены.
