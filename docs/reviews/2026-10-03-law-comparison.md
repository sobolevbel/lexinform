# Существенные изменения законопроектов: эксперименты на корпусе

Статус: исследование 03.10.2026, рабочий алгоритм версии `5769aed`.
Прототипы находятся в `tools/probe_law_comparison.py` и `tools/probe_law_mutations.py`;
они не подключены к pipeline. Все эксперименты офлайн, без новых вызовов моделей.

## Что следует считать изменением

Задача — обнаружить изменение действия закона для читателей, а не любое изменение букв.
Сумма, срок, условие, круг лиц, право, обязанность, процедура и вступление в силу требуют
проверки даже при замене одного символа. Подпись редактора, библиографическая сноска,
верстка и действительно равнозначная редакция не требуют нового анализа.

Нужны три разных результата: **подтверждённое техническое различие**, **существенное изменение**
и **неопределённость**. Последнюю нельзя превращать в «ничего не изменилось» по проценту
похожести. Уже существующий `ChangeReview` решает, существенны ли оставшиеся различия для
описания закона и иностранцев; новый эксперимент не заменяет его словарём синонимов.

## Данные и независимость проверки

Использованы все 1 028 текстовых пар прежнего `checks/out/92_transitions.json`: 560 RPW → druk
без правила происхождения и 468 RCL → druk. Это 1 698 отдельных извлечённых текстов.
Дополнительные 84 RPW без читаемого исходного текста и 130 связей без текста друка исключены;
48 пар не содержат распознаваемого тела закона. Сканам текстовый эксперимент ничего не доказывает.

Старый отчёт — проверка совместимости, а не независимая юридическая разметка. Поэтому отдельно
выполнены контрольные изменения реальных текстов, просмотрены новые совпадения и сверены
доступные результаты прежних 38 модельных проверок. Модельные ответы не запрашивались заново.

В отчёте сравнения сохраняются SHA-256 входных текстов, пути, решения каждой пары, абляции
правил и число сопоставленных строк таблиц. Скрипты запрещают перезапись результата и запись
внутрь корпуса. Их тесты защищают значимые числа, отрицания, ссылки, область действия,
перестановки коэффициентов и границы служебных фрагментов.

## Проверенные гипотезы

| Гипотеза | Результат | Решение |
| --- | --- | --- |
| Считать малый процент diff несущественным | В корпусе `2034` → `2033` у druku 545 занимает около 0,14 %, `5ac` → `5ad` у 2497 — около 0,25 % | Отвергнуть как основание пропуска |
| Игнорировать короткие слова и числа | Удаление `nie`, изменение срока и суммы могут быть короткими; возвращает B72 | Отвергнуть |
| Сравнивать набор слов/чисел без порядка | Контрольная перестановка двух сроков сохраняет набор токенов, но меняет нормы | Отвергнуть; порядок и связь значения с нормой обязательны |
| Сопоставлять по номерам статей | Не добавило надёжных автоматических совпадений; первый вариант ошибочно принимал три фрагмента без начала закона | Использовать для контекста смысловой проверки; неполный текст и повтор номера дают неопределённость |
| Убирать только подтверждённый технический аппарат | Подпись с должностью и именем, ограниченная библиографическая сноска, незаполненная дата приложения, `W ustawie dnia` → `W ustawie z dnia` | Перспективно; каждое правило имеет положительные и отрицательные примеры |
| Проверять таблицу построчно | Все 30 строк druku 1824 сопоставлены; изменение коэффициента, веса, отрицания или перенос коэффициента в другую строку отклоняется | Перспективно при наличии структуры исходных строк; остальное остаётся неопределённым |
| Отдельно сохранять числовые значения | Контрольные суммы, сроки и отрицания перестали исчезать в экспериментальном отпечатке | Необходимая защита перед оптимизацией числа повторных анализов |

Редакторский штамп удаляется только при распознанной должности и одном имени; последующий
текст нормы делает блок непригодным для удаления. Регулярное выражение «от подписи до конца»
без такой проверки отвергнуто. Библиографическая сноска допускает только её формулу и
перечень публикаций, а не произвольный текст до пустой строки.

Табличный прототип сохраняет последовательность строк, текст и значения каждой строки.
Он допускает перенос последней числовой ячейки внутрь текстовой ячейки той же строки:
так PDF извлёк Word-таблицу у druku 1824. Коэффициент не удаляется, проверяется его равенство.
После сопоставления сравнивается также весь оставшийся текст. Метод зависит от табуляций
в исходнике: после обрезки пригодные строки есть лишь у 5 пар (72 строки), сопоставлены 63
строки у 3 пар. Это не универсальный распознаватель таблиц PDF.

Это 653 автоматических пропуска вместо 618: восстановлены три регрессии B79 и найдены ещё

0,85–0,90. Ни один из семи сопоставленных случаев `material=true` не стал автоматическим
совпадением. Это полезная независимая проверка, но не полная разметка корпуса.

## Что обнаружили контрольные изменения

До diff pipeline проверяет `text_sha256` и `law_sha256`. Поэтому улучшение одного diff не
исправляет потерю смысла раньше него. Подтверждены два класса дефектов:

- [B80](../BUGS.md#b80): числа на отдельных строках принимаются за номера страниц, а
  удаление пунктуации и склейка токенов скрывают `92,67 zł` → `9267 zł`. В druku 810
  изменение табличной платы `1000` → `1001` проходит оба ранних отпечатка незамеченным.
- [B81](../BUGS.md#b81): широкое удаление тела сноски захватывает следующую норму. В druku
  342 можно удалить `nie` из условия о гражданстве без изменения `law_sha256`; в 1863
  срок `30 dni` → `31 dni` также не меняет этот отпечаток. Сам diff эти случаи видит,
  но раннее совпадение до него не доходит.

Это искусственные изменения реального материала, а не утверждение, что соответствующий
проект действительно менялся так в production. Особенно нельзя считать все изменения года
или запятой существенными: часть попадала в библиографические ссылки. Контекст сохраняется
для разбора каждого пропуска.

Экспериментальный защищённый отпечаток сохраняет числовые токены с разделителями и знаками,
не удаляет произвольные отдельные числа и не использует широкое удаление тела сноски.
В явном контексте `rok 202 6` допускается восстановление четырёхзначного года `rok 2026`,
с сохранением его значения; произвольные соседние числа не склеиваются.
Это более строгая гипотеза, а не новый формат сохранённых `law_sha256`.

Полный набор — 6 522 контрольных изменения. В таблице «пропуск» означает совпадение отпечатка
после изменения, а не автоматически подтверждённый дефект: изменения библиографических
публикаций могут быть техническими.

| Контрольное изменение | Проб | Пропустил `law_sha256` | Пропустил защищённый прототип |
| --- | ---: | ---: | ---: |
| Срок в днях | 1 228 | 6 | 0 |
| Год перед `r.` | 1 631 | 560 | 546 |
| Удаление отрицания | 934 | 28 | 0 |
| Удаление запятой между цифрами | 377 | 375 | 16 |
| Число на отдельной строке | 26 | 26 | 0 |
| Номер ссылки на статью | 1 594 | 3 | 0 |
| `cudzoziemców` → `obywateli polskich` | 81 | 2 | 0 |
| Перестановка двух разных сроков | 651 | 2 | 0 |

`text_sha256` тоже пропустил все 26 изменений отдельного числа; в остальных категориях
этих проб он изменения различил. Скрытые суммы, срок и отрицание дополнительно воспроизведены
через `World`: новый текст не вызвал ни проверки изменений, ни реанализа. Для срока и отрицания
использованы тела настоящих druk 1863 и 342, а не только короткий синтетический пример.

Оставшиеся 562 равенства защищённого прототипа разобраны по контексту: 557 относятся к
библиографическим ссылкам и сноскам, ещё 5 — к датам редакторского заверения или приложенного
обоснования. Это не пропущенные сроки действия нормы. Корпусный результат не доказывает,
что прототип распознает любые будущие форматы; в нём ещё используются части текущего
выделения тела закона и оформления страниц.

Защищённое представление и строки таблиц совпадают только у 591 пары. Это исследовательская
метрика, не готовое решение pipeline: 13 пар имеют тело короче действующего `MIN_LAW_CHARS=200`,
а проверка полноты документа и сканов остаётся отдельной обязанностью загрузчика. Из прежних
621 совпадения 49 теперь требуют дальнейшей проверки: например, списки изменяемых законов,
сноски о директивах, разрывы чисел и пробелы в диапазонах. Простой заменой существующего
отпечатка это не решается. Нельзя отказаться от числовой защиты ради красивого числа 653;
оставшиеся технические случаи нужно подтвердить структурно или смысловой проверкой.

Разбиение по статьям сравнимо у 954 пар и даёт 538 совпадений, но не добавляет новых надёжных
автоматических пропусков. Его полезная роль — точнее выбирать контекст изменённой нормы.

## Рекомендуемое устройство рабочего сравнения

1. **Исправить ранние отпечатки.** Версионировать канонизацию, сохранять числа и отделить
   доказанное оформление страницы от строк таблицы. Старый сохранённый отпечаток нельзя
   молча считать отпечатком нового формата. Повторное чтение старого файла допускается
   только при проверяемой связи с сохранённым анализом; иначе результат неопределённый.
2. **Выдавать основание технической эквивалентности.** Например: «ссылка на публикацию»,
   «редакторская подпись», «та же строка таблицы». Числа, ссылки и границы удалённых участков
   должны оставаться проверяемыми. Единственного процента похожести недостаточно.
3. **Передавать остаток на смысловую проверку.** Показывать полную затронутую норму и связанные
   определения, а не только двенадцать слов. Проверять изменение прав, обязанностей, сроков,
   сумм и круга лиц относительно существующей карточки. Уверенная равнозначная редакция
   сохраняет анализ; существенное изменение или недостаток контекста запускает полный анализ.
4. **Калибровать пороги по независимым примерам.** Сохранять пары «техническое / существенное /
   неясно» и объяснение. Включить реальные известные изменения и контрольные изменения норм;
   старый вывод самого алгоритма не является эталоном. Повторять корпусный прогон перед каждым
   изменением извлечения, обрезки, нормализации, отпечатков или сравнения.

Пункты 1 и 2 нужно внедрять совместно: освобождать больше пар от модели при сохранении
ошибочных ранних отпечатков небезопасно. Семантическая модель нужна для равнозначных
переформулировок; расширение списка игнорируемых слов не является её заменой.

## Воспроизведение

Из корня репозитория, с новым именем каждого выходного файла:

```bash
UV_CACHE_DIR=/private/tmp/lexinform-uv-cache uv run --offline python -m tools.probe_law_comparison \
  ../lexinform-corpus /private/tmp/law-comparison-run.json
UV_CACHE_DIR=/private/tmp/lexinform-uv-cache uv run --offline python -m tools.probe_law_mutations \
  ../lexinform-corpus /private/tmp/law-mutations-run.json
uv run --offline pytest -q tests/unit/test_law_comparison_probe.py
```

Продовые файлы, база, сообщения и корпус не изменялись. Требование корпусной проверки
закреплено в `AGENTS.md` и `CONTRIBUTING.md`.
