## Как устроены материалы

Частые формы: сопроводительное письмо, небольшой отчёт о ходе консультаций,
сводная таблица замечаний и ответов, отдельные письма с ответами участникам.
Файл может объединять несколько этих форм. Имя файла, расширение и папка
не гарантируют внутреннюю структуру или наличие решения министерства.

| Элемент | Содержание и ценность |
| --- | --- |
| Введение | Версия проекта, сроки, способ консультаций, круг участников. Небольшое; даты и новые окна участия сохраняются отдельно от повторяющейся процедуры. |
| Номер, автор, статья | Обычно короткие поля. Необходимы для атрибуции, поиска источника, связи с нормой и другими замечаниями. |
| Замечание / предложение редакции | Основной запрос участника; иногда включает цитату нормы целиком или несколько предложений. Часто занимает большую часть текста. |
| Обоснование | Может быть отдельной колонкой или частью замечания. Бывает длиннее предложения; здесь встречаются единственное объяснение последствия, исключения, цены и сроки. |
| Ответ министерства | Принятие, отказ, частичное принятие, объяснение или отсылка. Высокая ценность, но короткий ярлык не заменяет полный ответ. |
| Приложения | Расчёты, финансовые таблицы, проекты формулировок, дополнительные позиции. Ценность зависит от связи с отобранным вопросом. |
| Оформление | Повторные заголовки, колонтитулы, адреса, подписи. Обычно менее ценно; контакт для замечаний или дата подписи могут иметь самостоятельный смысл. |

После исключения побайтных копий просмотрены 362 DOCX/DOCM и 342 таблицы верхнего
уровня с 24 523 физическими строками. У 129 таблиц меняется число ячеек по строкам;
обнаружены 2 672 элемента вертикального объединения. В 228 таблицах начало содержит
узнаваемые обозначения замечания и ответа. Это не 228 полностью разобранных схем.

Схемы бывают на три, четыре, пять и шесть колонок; в одном файле порядок меняется.
Например, `800893` начинается сразу с трёхколоночных данных без заголовка;
`801504` содержит таблицы на шесть и пять колонок, продолжения начинаются без шапки.
Нельзя назначить фиксированные номера колонок всем документам или разбить PDF
на строки по переводу строки.

По осторожной автоматической разметке заголовков 204 таблиц (18 346 строк с
подходящей шириной), около 70% текста ячеек приходится на замечания и предлагаемые
редакции, иногда вместе с обоснованием; 20% — на ответы, 5% — на отдельные
обоснования, 4% — на авторов и ссылки на нормы. Это профиль распознанной части,
а не всех форматов. Медиана доли предложений в одной таблице — 70%, ответов — 22%.
Отдельной колонки обоснований у многих таблиц нет; это не означает отсутствия
обоснований в тексте замечания.

## UD187: куда уходит объём

[Исходный DOCX](https://legislacja.rcl.gov.pl/docs//2/12398102/13129924/13129928/dokument780621.docx)
содержит 616 строк замечаний в основной таблице и вложенную финансовую таблицу.
Извлечённый текст — 1 733 833 символа; вместе с текущим проектом — 2 187 739.
Ни одной полностью одинаковой строки в основной таблице нет.

| Поле основной таблицы | Символов после свёртки пробелов | Доля текста ячеек |
| --- | ---: | ---: |
| Автор | 26 393 | 1,6% |
| Статья / предмет | 35 381 | 2,1% |
| Предложение | 497 223 | 29,7% |
| Обоснование | 705 432 | 42,1% |
| Ответ MZ | 410 950 | 24,5% |

Самая длинная строка — 23 625 символов; девять длиннее 10 тысяч, две длиннее
20 тысяч. Лимит на строку с обрезанием хвоста может отрезать именно ответ.
Номера замечаний хранятся преимущественно как автонумерация Word (`numId=95`),
и обычный текстовый экстракт их не выводит. Физический индекс строки в этом
аудите не следует автоматически считать номером, на который ссылается MZ.

Повторы ответа можно хранить один раз, но нельзя склеивать разные предложения
только из-за одинакового «Uwaga zasadna». Ответы «j.w.» и «uzasadnienie w pkt…»
требуют сохранения связанных строк; ошибочную или неоднозначную ссылку нельзя
разрешать догадкой. Пустую ячейку автора нельзя всегда заполнять предыдущим
автором: объединение проверяется по XML, а не по одному тексту.

## Что доказано и что ещё проверить

Вручную просмотрены 19 положительных контрольных строк из трёх документов.
Словарь иностранной тематики сохраняет только четыре из них. Это контрпримеры,
а не оценка полноты по всей популяции. Обратимое кодирование прошло 55 391
проверку с изменениями дат, сумм/сроков, отрицаний, круга лиц и ссылок на статьи.
Проверка подтверждает сохранение различий и восстановление ячеек, а не качество
смыслового отбора или ответа модели.

Размеры измерены в символах, не в токенах провайдера. Структурный разбор PDF,
сканов, legacy DOC и содержимого ZIP не проверен этим табличным экспериментом.
Сохранение исходников не равно качественному OCR. Платного A/B полного и
сокращённого разбора не было, поэтому безопасный процент смыслового сокращения
и попадание UD187 в $2 этим аудитом не установлены.

## Предлагаемый порядок обработки

1. Сохранить исходники и хеши, убрать точные копии с полным списком источников.
2. Извлекать структурные единицы: автор, исходный номер, статья, предложение,
   обоснование, полный ответ. Поддержать продолжения, объединения и отсылки.
3. Отбирать связанные вопросы отдельным триажем. Модель возвращает ID строк
   и причины отбора, без переписывания доказательств. Учитывать как общие условия
   для жителей, так и новые темы вне первоначальной карточки. Неясное сохранять.
4. Подгружать целые выбранные строки, их зависимости и нужные нормы текущего
   проекта. Для утверждения «вошло в текст» нужна соответствующая предыдущая
   версия; ответ министерства этого не доказывает.
5. Если выбранный материал всё ещё велик, разбирать по тематическим группам
   с общим бюджетом и последующим объединением доказанных выводов. Нельзя
   объявлять полный разбор, когда часть вопросов не прочитана.

Следующая проверка — независимая разметка строк разных проектов, затем A/B
полного и отобранного текста: пропуски важных вопросов, правильность исходов,
условия, точные цитаты, размер запросов и стоимость. До неё смысловое
отсечение не включать в production.

## Воспроизведение

Из checkout lexinform, с тем же установленным окружением:

```bash
uv run python ../lexinform-corpus/scripts/consultation_docs.py \
  --root ../lexinform-corpus
uv run python ../lexinform-corpus/checks/check_consultation_pruning.py \
  --root ../lexinform-corpus \
  --output ../lexinform-corpus/checks/out/consultation-pruning-2026-10-14.json
```

Первый скрипт возобновляет сбор и сохраняет ошибки; второй работает офлайн.
JSON хранит размеры, группы точных копий, контрольные строки, мутации и исключения.
