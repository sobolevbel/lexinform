# Аудит больших изменений 13–14 октября

Статус: исторический аудит · 14 октября 2026. Проверен код
`810f14705eca24789cd3c838e92e57d7243fd280`, база сравнения `3d187d5`.
Поведение приложения в ходе аудита не изменялось. Текущий статус находок —
в [реестре B91–B95](../BUGS.md#b91).

## Результат

Найдены пять воспроизводимых дефектов, восемь падающих вариантов регрессий.
Основные риски находятся в совместной работе доставки и операторского восстановления.
Зелёные существующие тесты и высокое покрытие не обнаруживали эти последовательности.

Итоговый offline gate после добавления проверок: 2190 passed, 8 xfailed,
32 deselected; strict mypy проверил 269 файлов, Ruff check/format и diff check прошли.
При `--runxfail` отдельный набор аудита даёт 8 failed и 7 passed.
Strict docs build и проверка ссылок/якорей прошли; страница и переход к B91
проверены в локальном браузере.

| Дефект | Приоритет | Подтверждённое поведение |
| --- | --- | --- |
| [B91](../BUGS.md#b91) | P1 | Queued хвост дайджеста обходит исчерпанный лимит предыдущей части |
| [B92](../BUGS.md#b92) | P1 | Dismiss части дайджеста оставляет его хвост и события без пути завершения |
| [B93](../BUGS.md#b93) | P2 | Dismiss раннего продолжения оставляет поглощённый статус queued |
| [B94](../BUGS.md#b94) | P2 | Полностью доставленные многочастные карточки больше не обновляются |
| [B95](../BUGS.md#b95) | P3 | Новый unknown продолжения не делает первый прогон ошибочным |

Регрессии находятся в `tests/scenario/test_recent_changes_audit.py`.
Ожидаемое исправленное поведение отмечено strict xfail: это сохранённые открытые дефекты,
а не ослабление production-проверок. `--runxfail` включает проверки без этих отметок.
Контрольные случаи проверяют cap последней части, confirm/retry первых двух частей,
dismiss последнего продолжения и сохранность digest membership после retention.

## Объём

Сравнение включает 31 коммит без merge-коммитов, 150 файлов,
15 135 добавленных и 1 296 удалённых строк. Проверены взаимосвязи следующих изменений:

- Редакционные имена, независимые importance/urgency, routine roundups и суточная очередь.
- Освежение участия перед отправкой, delivery-only runs и операторские alerts.
- Неизвестные исходы, поздние решения и дополнение голосов.
- Digest-only ownership, сохранённые физические части, retry/confirm/dismiss.
- DocumentReview, batch purposes, cost guards и пауза новых разборов.
- Продолжения карточек и обновлений, сохранение родителей и payload при retention.
- Миграции v36–v44, восстановление RPW после 404, binary Accept и выбор RCL текста.
- Wiring, CLI, shell-ветви workflow, HTML, строки статуса и даты событий.

## Проверки кода и тестов

До добавления новых регрессий полный offline gate прошёл: pytest, strict mypy,
Ruff check и format. Coverage с включёнными ветвями составил около 91%.
Значимые пробелы до аудита: `message_parts` — 84%, `document_reviews` — 60%,
`sources` — 69%; последнее связано в том числе с отключёнными разборами.
Эти проценты показывают исполненные ветви, а не качество выводов или завершённость ревью.

Все 21 local_http CLI test прошли на локальном сервере-заглушке.
Первый запуск внутри песочницы получил PermissionError при bind;
повтор с разрешённым loopback выполнил те же тесты успешно.
Никакие live integration tests с отправкой сообщений или платными вызовами не запускались.

Добавлен `tests/scenario/test_delivery_recovery_properties.py`:
Hypothesis генерирует 25 последовательностей до 15 шагов из restart, drain, retention,
смены дня и confirm/retry/dismiss. Restart создаёт новый World/Container из dump,
поэтому проверка не зависит от прежних кешей и множества attempted.
Модель ожиданий проверяет запрет resend unknown, статусы потомков, неизменность
сохранённого HTML и защиту root payload до завершения цепочки. Эти проверки прошли.
Они относятся к отдельной многочастной карточке; свойства группы и дайджеста
проверяются отдельно, включая подтверждённые отрицательные сценарии B91–B93.

Существующий набор сценариев дополнительно покрывает workers=1/4, DST Warsaw,
границы суточного ожидания, исчезновение/сокращение окна участия, frozen retry,
защиту группы и операторский override. Эти тесты прочитаны вместе с реализацией
и выполнены в полном gate, а не заменены результатом старого запуска.

## Архитектура и чистота кода

Импортов `lexinform.adapters` внутри services не найдено. В проверенных изменениях
время берётся из Clock, source-specific выбор документов остаётся в TextSource seams,
SQL миграций append-only. Новые параметры и модели не потребовали обхода strict typing.

Главное архитектурное замечание — несколько реализаций одного жизненного цикла:
`Poster._send`, `PublishingService._send`, `send_continuations` и `DigestService._send_parts`.
У них различаются проверки attempts, распространение ошибки, завершение хвоста
и подсчёт физических сообщений. B91–B93 и B95 показывают конкретные последствия.
Размер `posting.py` сам по себе не доказательство дефекта; предмет разделения —
владение переходами и эффектами доставки.

Рекомендуется сначала устранить подтверждённые дефекты, затем выделить общую
оркестрацию физических отправок с явно передаваемыми ограничениями, порядком,
неопределённым исходом и эффектами конкретной части. Repository должен сохранять
атомарность и membership, но не выбирать редакционный маршрут. Различия между
дайджестом и reply chain должны оставаться явными, а не скрываться за одним bool.

Для B94 нужна отдельная политика обновления завершённой карточки из нескольких частей.
Текущий guard запрещает даже безопасные случаи; удаление guard без решения лимита
и идентичностей продолжений также было бы дефектом.

У базового pytest есть ResourceWarning незакрытых SQLite в сценарном harness.
Они не превратились в падения и не классифицированы как production-дефект;
это отдельная задача уборки тестовых ресурсов. Новая state-machine закрывает
старый repository при restart и конечный repository в teardown.

Workflow использует поддерживаемое `queue: max` вместе с `cancel-in-progress: false`.
Допустимость проверена по [официальной документации GitHub](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency).
Shell-сценарии с подставными uv/curl проверяют hourly inbox, dry run и четыре
исхода сохранения state. Реальную очередь GitHub и production alerts аудит не запускал.
