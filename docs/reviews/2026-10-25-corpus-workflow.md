Статус: локальное исследование и первый инструмент улучшения, 25 октября 2026.
Runtime-база: `4fbce754bd0b3fc59ba7ac5b6d41513f578cfed5`, со стадией J053 `c793c42`.
Корпус читался без изменений, скачиваний и модельных вызовов. Свежая опись ниже относится
к RCL documents и историческим кандидатам с autopoprawki; остальные числа имеют свои даты.

Главный следующий шаг — связать существующие проверки, входы, разметку и результаты одним

или скачивание всего RCL сейчас не нужны для проверенного среза.

## Свежая проверка RCL и очередь действий

Добавлен development-only `tools/corpus_health.py`. Он читает индекс и исторические проекты,
строит связи кандидатов с URL/стадией/полем, проверяет наличие оригиналов и, с `--check-text`,
ограниченно читает gzip/UTF-8. Ничего не скачивает и не переизвлекает. Результат `recorded`
означает завершённую опись, а не признание всех данных правильными.

| Измерение 25 октября | Результат |
| --- | ---: |
| Проиндексированные RCL documents | 10411 |
| Существуют оригинал и кеш извлечения | 10411 |
| Непустой читаемый gzip/UTF-8 | 10234 |
| Пустые извлечения | 177 |
| Отсутствующие дополнительные документы в amendment cohort | 7 |
| Прочитанные и зафиксированные SHA paths | 11237 |
| Повреждённые gzip/UTF-8 в этом проходе | 0 |

Наличие оригинала не означает проверенную целостность его содержимого: health tool не читает
все raw bytes и не проверяет подписи, структуру PDF/ZIP или правовую роль.
Старая таблица README с 9221 RCL file датирована 4 октября; текущий индекс уже содержит
добавление консультаций и 10411 records. Эти значения описывают разные снимки.

Среди 177 empty caches: 118 ZIP и 59 PDF; по старому folder label — 136 project, 12 letters,
28 response, одна position. Это приоритетная локальная очередь повторного извлечения текущим
экстрактором в новую генерацию: часть причин может относиться к прежним версиям парсера.
Факт восстановления текстов новым extractor здесь не измерен. Ни один empty ZIP не следует
объявлять сканом без проверки его содержимого, а empty PDF — бессмысленным для читателя.

в этой копии нет оригиналов и записей `documents/index.json`. Извлечение без сети их

| RCL/12294859 | 300535, 300536 | Альтернативные кандидаты основного документа |

извлечение и повтор тех же исторических cases. HTTP/HTML вместо PDF/ZIP записывается как
ошибка источника, не принимается за документ. Downloads сохраняются под исходными ID.

Далее по приоритету:

1. Перепроверить три известных недоступных ZIP консультаций — 787418/787427/787416.
   Последний сохранённый checkpoint от 14 октября: 1198 wanted, 1195 downloaded, complete=false,
   finished=true, три ответа HTML вместо attachment, 29 empty text sources. Это исторический
   статус; новые запросы сейчас не выполнялись. Пустые тексты проверять локально до повторной сети.
2. Сформировать **новый датированный snapshot метаданных** Сейма/RPW/supplements и сравнить

   сентября и снимком 3 октября; это не измерение текущего дефицита на 25 октября.
   Сначала вычислить актуальный diff, затем скачивать документы, влияющие на проверяемые пути.
3. Локально перепроверить 118 empty ZIP и 59 empty PDF, сохранив старый кеш и новый результат
   раздельно. Появившийся текст ещё требует проверки роли/принадлежности. Это делается до
   дополнительных загрузок; необходимость OCR устанавливается содержимым PDF.
4. Добавить материалы, которых не хватает конкретному benchmark: связанные редакции,

## Что действительно упростит работу

### 1. Надёжно сохранять результаты и генераторы

Самый высокий приоритет. В этой сессии `/private/tmp` перестал содержать J053 artifacts после
смены среды; похожая потеря уже отмечена в J043. Это вынуждает экспортировать старый commit
и заново выполнять дорогой baseline. Отсутствующий артефакт нельзя восстановить по итоговым числам.

Зафиксировать единый run manifest: run ID, task/stage, base/current code, hashes входов,
профиль/опции/версии библиотек, populations/exclusions, status, artifact paths/SHA и команду повтора.
Содержательные selectors, mutation generators и acceptance checks держать в versioned tools,
а не только в `/tmp`. Крупные отчёты хранить в постоянном каталоге отдельно от сырья;
малый manifest/сводку и diff решений — в Git. Утвердить копирование важных артефактов перед
очисткой workspace; для этого не требуется сейчас выбирать S3 или переносить raw files.

Зафиксировать и локальные предпосылки offline gate. При повторном прогоне один тест упал:
исчез словарь `tiktoken` из временного кеша, а библиотека попыталась скачать его по сети.
Словарь `o200k_base` получен штатным loader с проверкой expected SHA в `.cache/tiktoken`.
Для offline запусков используется явный `TIKTOKEN_CACHE_DIR`, команды записаны в tools README.
Это не модельный вызов и не изменение лимитов/оценки токенов; первая загрузка словаря требует сети.

### 2. Общий запуск и просмотр различий поверх существующих runners

Развить уже имеющийся `make corpus-check`, не писать вторую систему с нуля. Реестр suites
должен подключать PDF pages, Word blocks/notes, input coverage, cost fitting, amendments,
selection, transitions и Senate, указывая required inputs, стоимость и exclusions каждого.
Селекторы cases и описи делаются отдельными воспроизводимыми командами.

Один запуск должен делать preflight → baseline/compare → отчёт изменившихся решений.
Отдельный diff показывает документ, роль, state/limitations, hash текста, retained ranges,
размер metadata и причину изменения. Отличать `not_run`, ошибку, новый/удалённый case и
разрешённое изменение; непустой exit 0 при пустой population запрещён.

Кешировать дорогую работу по raw SHA + extractor/options/contract version. SHA одинаковых
байтов позволяет повторно использовать извлечение, сохраняя все URL и роли как отдельные связи.
Параллельные рабочие checkout фиксируются до начала replay: добавление tool в середине
измерения уже приводило к полезному срабатыванию changed-code guard.

### 3. Проверять корпус перед долгим replay

Начало сделано health tool. Расширить его на Sejm/RPW/Senate и другие required cohorts.
Очередь должна различать `fetch_source`, `reextract_text`, `review_empty_text`, metadata gap,
role conflict, missing relation, source refusal и oversized input. Не каждую ошибку лечит сеть.
Каждая запись привязана к cases, URL, original SHA и причине необходимости; приоритет определяется
тем, какой обязательный benchmark блокируется. Отчёт об отсутствии текста не объявляет файл сканом.

### 4. Дополнять разметку отношений и диапазонов

Расширить существующие `CorpusCase`/evidence manifests, где уже есть oracle, basis и split.
Для сложного комплекта нужны: принадлежность инициативе, роль bill/annex/support/proposal,
связь приложения с конкретным законом, дата именно редакции, обязательность части для операции,
подтверждающие цитаты и координаты. Для текстового преобразования — что должно сохраниться
и какое удаление допустимо. Для скана — физическая страница нормы и качество текстового слоя.

Метка имеет происхождение: human_review, source_metadata, synthetic_invariant или
machine_baseline, плюс reviewer/date/evidence scope. Не повышать head/tail reading до полного
прочтения; `unknown` — допустимая разметка. Разногласия reviewer хранить как конфликт.
Старые labels `document_kind` остаются полезным regression baseline, но не gold standard.

Первую ручную очередь брать из новых changed decisions, empty/ambiguous bundles, mixed scans,
обязательных приложений и misleading names. Уже использованные E0/E2 cases оставить regression.
Новый holdout формировать по группам всей инициативы RCL→RPW→druk, исключая утечку одной
редакции или переупаковки в другой split. Сначала восстановить группы существующих labels;
общую точность корпуса до этого не заявлять.

В `INDEX.cases` полезно добавить адресуемые группы `bundle.self_amendment`,
`bundle.required_annex_missing`, `selection.name_content_conflict`,
`input.normative_after_osr`, `input.generated_marker`, `scan.relevant_beyond_triage`.
Первые группы генерируются как кандидаты из inventories, затем получают проверенные labels;
автоматическое попадание в группу ещё не подтверждает правильность ожидаемого решения.
Для ручной очереди достаточно локальной HTML-страницы: рядом источник, выделенная цитата,
предыдущее/новое решение и кнопка сохранения отдельной аннотации. Новая база и веб-сервис
для начала не требуются; результаты review хранятся отдельно от машинных ожиданий.

### 5. Развести версии исходных снимков и производных

Не перемещать и не переименовывать `documents/files/{id}.*` и прочие download paths: это resume
keys действующих collectors. Сначала добавить sidecar manifests с URL, fetched_at, SHA/size,
collector/version и статусом ответа. При изменении байтов по одному URL сохранять новый snapshot,
а не выдавать новый файл за прежний исторический источник.

Извлечение получает raw SHA, extractor/options/contract и собственный SHA. Пересчёт пишет новую
генерацию derived данных до обновления указателя; нынешний `rederive.py` умеет dry-run, но обычный
режим перезаписывает кеш/индекс. Старые benchmark inputs нельзя терять при таком пересчёте.
Поисковый SQLite-индекс допустим как пересоздаваемая локальная производная, когда JSON станет
неудобен; сейчас для health и очереди из семи файлов он не нужен.

### 6. Разделить проверку на три уровня

| Уровень | Что запускать | Когда |
| --- | --- | --- |
| CI | Небольшие настоящие regressions, schemas, manifest guards, meaningful mutations | Каждый commit |
| Локальный профиль | Все относящиеся к изменению cached cases и raw cases затронутого формата | Перед принятием изменения |
| Полная приёмка | Все required profiles плюс reviewed decision diff, independent labels для policy change | Перед изменением общего правила/выпуском |

Это группировка существующих проверок, не разрешение пропускать реальный corpus gate при
изменении extraction/trim/normalization/comparison. Полный проход выполняется, когда он нужен,
а дорогие неизменные extraction результаты используются по проверенной identity.

## Порядок следующих работ

1. **Уже реализовано локально:** bounded RCL health report, action queue с dependency provenance,
   тесты, свежий read-only проход и сохраняемая компактная сводка. Оригиналы не менялись.
2. Вынести selectors/acceptance из временных scripts, добавить run registry и постоянный
   output root; перенести туда только реально доступные артефакты, остальные пометить missing.
3. Адресно загрузить семь файлов и перепроверить три consultation refusals отдельным collector
   run; локально переизвлечь empty ZIP/PDF в отдельную генерацию. Повторить соответствующие
   cases; health не выполняет эти исправления автоматически.
4. Подключить специализированные suites и единый diff к существующему runner.
5. Запустить очередь ручной разметки отношений/coverage и новый групповой holdout;
   затем решать, каких дополнительных raw/snapshots не хватает именно этим проверкам.

Первый Git check был заблокирован usage limit approval review; после времени сброса повтор
успешно подтвердил main. Результат commit/push и общих проверок фиксируется в
[журнале реализации](../plans/2026-10-22-document-architecture-progress.md).
Сохранение этого отчёта само по себе не означает deploy.

Реализация предложений и последующие измерения ведутся в
[отдельном checklist и журнале](../plans/2026-10-25-corpus-improvements.md).
Числа выше относятся к исходному health snapshot, не заменяются новыми результатами.
