## Какие признаки используются

Выбор начинается со стадии `SenatePosition` и привязанного к ней druku.
У объявленных читаемых приложений проверяются:

1. Самостоятельный заголовок `UCHWAŁA / SENATU RZECZYPOSPOLITEJ POLSKIEJ`,
   дата и предмет постановления. Перед ним допускается передающее письмо;
   цитата внутри отчёта или обоснование не подходят.
2. Формула рассмотрения принятого Сеймом закона и утвердительное решение
   `wprowadza do jej tekstu następujące poprawki` либо единственная поправка.
   Отрицание, принятие без поправок и отклонение не становятся поправками.
3. Сами операции изменения текста и окончание постановления. Пустая внутренняя
   страница не считается извлечёнными поправками. Нумерация и ссылка на статью
   не обязательны: встречаются поправки к преамбуле и бюджетным таблицам.
4. Согласие двух упоминаний предмета внутри постановления и совпадение с названием
   druku либо связанного процесса. Сходство строк не заменяет совпадение;
   опечатки и изменения сферы действия автоматически не прощаются.
5. Совпадение даты с датой стадии либо `documentDate` druku. Это независимое
   точное подтверждение, а не допуск по близости дат. Для IX/1712 стадия в свежем
   API датирована июлем, постановление и druk — октябрём; для X/3132–3133
   постановление и druk подтверждают следующий день относительно стадии.

Разрядка букв допускается только при поиске структурных формул. Числа,
отрицания, круг лиц, ссылки и текст изменений не нормализуются перед моделью.
Удаляется передающее письмо; обоснование, включённое в выбранный документ,
сохраняется. Самостоятельное обоснование не подменяет нормативный текст.

Проверяются все объявленные Word-приложения. При противоречащих версиях выбор
останавливается. Подтверждённый Word предпочтительнее извлечения PDF; если его
нет, проверяются PDF. Имя используется только для определения поддерживаемого
расширения. Именной и числовой шаблон удалён.

В `TextDocument` фиксируются SHA-256, предмет и фактическая дата постановления.
Перед подготовкой анализа документ проверяется повторно. Текст поправок
нельзя молча обрезать бюджетом. Правило общее для tracking и `/amendments`;
исторический снимок сообщения, очередь batch и история доставки сохраняются.

## Пределы и сознательные остановки

Это консервативный набор проверок, а не доказательство универсального формата.
Из 30 неподтверждённых источников 23 дают скан, письмо, частичный или повреждённый
текстовый слой. В частности, у X/2103 извлекается обоснование, но не сами поправки;
у пяти PDF VIII созыва OCR повреждает заголовки, слова и ссылки вроде `art. 47`.
Извлечение многих символов само по себе не подтверждает пригодность текста.
Семь ранее читаемых документов теперь останавливаются:

| Druk | Причина |
| --- | --- |
| VIII/1840 | `sądowych` в заголовке, `sadowych` в повторном названии |
| IX/2219 | В заголовке пропущено `Służby` перед `Celno-Skarbowej` |
| X/887 | В повторном названии лишнее `o` |
| X/2068 | В повторном названии пропущено `o` |
| IX/1211 | В Word нет окончания постановления; PDF является сканом |
| IX/3505–3506 | Постановления датированы 14 июля, стадия — 13 июля, druk — 19 июля |

Для IX/1211 изображение страницы PDF подтверждает короткую поправку и подпись,
которой нет в Word. Это реальный пропуск консервативного распознавания, а не
доказанное отсутствие поправок. Поэтому результат нельзя объявлять «без регрессий».
Полный список остановок и прежних источников находится в `replay-final.json`.

Из двух исключённых записей VIII/1538 является законодательной инициативой Сената;
у X/713 в актуальном процессе 601 стадия поправок не содержит `printNumber`.
Восстановление отсутствующей связи не входит в это изменение.

Дополнительно сопоставлены 297 читаемых пар Word/PDF. Простое сравнение после
удаления пробелов не доказывает эквивалентность: автоматическая нумерация Word
и порядок чтения таблиц отличаются. Например, IX/1257 в PDF извлекает коэффициент
`0,65` посреди перенесённого описания ячейки, тогда как Word сохраняет строку
таблицы. У IX/655 различаются сами законы. Диагностические нормализации и hunks
сохранены в `format-comparison.json` и не используются для признания поправок
несущественными. Равенство Word и подписанного скана повсеместно не доказано;
новый OCR не выполнялся, батчи с изображениями не отправлялись.

## Воспроизводимость и проверки

```bash
uv run python -m tools.replay_senate_documents \
  ../lexinform-corpus/sejm/supplements/2026-10-16-senate-resolutions \
  ../lexinform-corpus /private/tmp/senate-replay-new.json
```

Выход должен быть новым файлом вне входных корпусов. Проверка использует рабочий
`TextLoader`, выбор источника и проверку сохранённой идентичности. Извлечения
зафиксированы рабочими экстракторами; SHA-256 исходных файлов проверяется повторно.
В отчёте есть хеши входов, кода, решения по каждому druku, прежний источник,
причины остановок и полный перечень отрицательных контролей.

Переименование и перестановка приложений не меняют выбранное содержание.
На всех 694 выбранных текстах прошли **4 858 инъекций**: дата, сумма, отрицание,
круг лиц, ссылка, отдельные числовые строки и десятичная сумма. Каждый фрагмент
сохраняется в тексте, ключ анализа меняется. Ещё **12 сценариев на копии production
state** проверяют настоящий DOCX 3213, workers=1/4, batch, восстановление базы и
редактирование сообщения 107 с сохранением оригинала. Провайдер и Telegram — fakes.

Локальный gate: pytest, strict mypy, Ruff и проверка diff; отдельно пройдены
сценарии восстановления доставки с `--runxfail`. Изменений CLI или HTTP-адаптера
нет, `local_http` для этой правки не запускался. Отправка в production не выполнялась.
