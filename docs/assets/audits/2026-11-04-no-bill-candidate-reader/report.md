# Compatible no-bill-candidate reason reader

The actual package-policy branch with no main bill candidate can leave a normative annex
outside the supporting-only unsupported selection. No chosen family exists there, so
family_exclusion would misdescribe the observed decision. The compatible reader adds the
single policy-excluded reason no_bill_candidate before a writer can emit it.

One public-model roundtrip unit is added. Selection, source policy, trimming, producer
activation, schema, defaults and identity algorithms are unchanged. This stage does not
claim the runtime branch has been captured or accepted; B qualification must prove that.
Ambiguous-version composition uses existing version_conflict only on its actual branch.

On fixed state105de577,all8legacy traces keep exact JSON/ID/column values; ordinary doctor
is exact, optional candidate doctor validates8rows with no findings, inputDB unchanged.
This is a historical pin. Reader deployment must precede publication of the new reason.

Before the source edit, the root also froze a cached RCL-stage reference:4276cases with
7599readinputs and1383missing inputs (complete_population=false). An independent worker
matched all results/counts/input/missing/exclusion fields. This is a reference for future
writer parity, not raw archive coverage or a claim that missing views are irrelevant.
No extraction corpus acceptance is inferred from this reader-only enum addition.
